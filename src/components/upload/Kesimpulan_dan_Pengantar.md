## 3. Bab 4 Kesimpulan

*Salin teks di bawah ini sebagai draf Bab 4 Kesimpulan Anda:*

# 4 Kesimpulan

Dari 38 pengujian fungsionalitas yang telah direncanakan dan dieksekusi secara otomatis menggunakan Selenium IDE dan Selenium WebDriver pada sistem pemantauan kualitas udara CarbonSense, seluruh 38 pengujian dinyatakan berhasil (**pass**) dengan persentase keberhasilan sebesar **100%**. Selama siklus pengujian berlangsung, tim penguji berfokus pada pengujian aspek fungsionalitas dasar seperti modul login dan registrasi, alur wajib pengisian kuesioner onboarding kesehatan, validasi parameter penautan perangkat (*QR Code Device Binding*), hingga sinkronisasi data sensor MQ135 secara real-time.

Pada awal tahap pengembangan pengujian, tim penguji sempat mengidentifikasi beberapa *defect* penting, di antaranya adalah:
1. Validasi batas panjang karakter registrasi akun (*username* dan *password*) yang belum terikat secara ketat.
2. Penautan perangkat fisik menggunakan tautan URL parameter (`login?device=...`) yang sempat menerima sembarang kode perangkat.

Namun, kendala tersebut telah berhasil diselesaikan secara tuntas. Saat ini, registrasi akun pengguna hanya dapat berhasil jika kata sandi diisi minimal 6 karakter. Sementara itu, untuk penautan alat lewat scan QR, sistem kini memvalidasi parameter *Device ID* secara ketat terhadap database admin; apabila parameter yang dikirim di luar dari yang didaftarkan oleh admin, halaman penautan secara otomatis dikosongkan demi mencegah terjadinya penautan ilegal. 

Untuk pengembangan dan peningkatan sistem di masa mendatang, tim penguji memberikan beberapa saran perbaikan sebagai berikut:
1. **Peningkatan Manajemen State Pengguna**: Disarankan untuk menambahkan animasi pemuatan (*skeleton loading state*) saat sistem menyinkronkan data parameter PPM kualitas udara dari database Supabase PostgreSQL ke dashboard frontend guna meningkatkan kenyamanan visual pengguna.
2. **Validasi Sisi Server (Backend Validation)**: Perlu ditambahkan validasi skema yang lebih ketat pada lapisan backend (*database constraint*) untuk parameter penautan perangkat, sebagai proteksi lapis kedua selain pengosongan halaman pada antarmuka frontend.
3. **Mekanisme Penanganan Gangguan Sensor**: Disarankan untuk menambahkan sistem peringatan berupa notifikasi surat elektronik (e-mail) otomatis kepada pengguna apabila status perangkat terdeteksi *Offline* atau tidak aktif selama lebih dari 12 jam berturut-turut.
