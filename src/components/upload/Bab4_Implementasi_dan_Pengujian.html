4.1 Implementasi

Bagian ini menjelaskan secara rinci mengenai tahap implementasi sistem aplikasi CarbonSense. Penjelasan mencakup persyaratan sistem minimum (baik perangkat keras maupun perangkat lunak), langkah-langkah penyebaran (deployment) aplikasi pada lingkungan pengembangan lokal, serta deskripsi fungsional dari halaman antarmuka pengguna yang telah dibangun.

4.1.1 Persyaratan Sistem (System Requirements)

Untuk memastikan aplikasi CarbonSense dapat dibangun, dijalankan, dan diuji dengan optimal, telah ditetapkan spesifikasi minimum lingkungan perangkat keras dan perangkat lunak yang tercantum pada Tabel 4-1 dan Tabel 4-2 di bawah ini.

4.1.2 Penyebaran Sistem (System Deployment)

Penyebaran sistem CarbonSense dilakukan pada lingkungan pengembangan lokal (local development environment) dengan langkah-langkah terstruktur sebagai berikut:

  1. Mengunduh Source Code Aplikasi: Source code diperoleh dengan melakukan cloning repositori Git proyek menggunakan perintah git clone https://github.com/BreadOcT/CarbonSense2.git atau mengunduh file biner ZIP secara langsung dan mengekstraknya ke direktori lokal (misal: C:\projects\magicpath-project).
  2. Instalasi Dependensi Node.js: Membuka terminal pada direktori proyek (root) dan folder server, kemudian menjalankan perintah npm install untuk menginstal semua modul dependensi yang tercantum di package.json.
  3. Konfigurasi Database & Environment Variables: Membuat file .env di dalam folder server untuk menyimpan kredensial database (Supabase PostgreSQL / Local MySQL), JWT Secret key, dan API Key untuk asisten cerdas Gemini.
  4. Menjalankan Aplikasi: Menjalankan perintah npm run dev pada terminal root. Perintah ini menggunakan utilitas concurrently untuk menjalankan server frontend (Vite pada port 3000) dan server backend (Express.js pada port 5000) secara bersamaan. Aplikasi siap diuji di alamat http://localhost:3000.

4.1.3 Implementasi Antarmuka Pengguna (User Interface)

Implementasi antarmuka pengguna pada sistem CarbonSense diklasifikasikan berdasarkan peran pengguna sebagai berikut:

  1. Antarmuka Web App Klien (User / Pengguna Terdaftar):
    • Halaman Login & Register: Menyediakan form isian kredensial yang minimalis dengan penanganan error validasi isian secara dinamis.
    • Halaman Onboarding (Profil AI): Kuesioner interaktif mandatori bagi pengguna baru untuk mengklasifikasikan kerentanan kesehatan penghuni ruangan demi konfigurasi batas alarm sensitivitas gas PPM.
    • Halaman Select Device (Pilih Alat): Antarmuka yang memverifikasi ID perangkat terdaftar dan menautkannya ke email pengguna melalui QR Code atau input manual.
    • Halaman Dashboard Monitoring: Menyajikan indikator visual real-time kadar gas PPM MQ-135, grafik tren historis (Recharts) interaktif dengan filter tanggal (*DatePicker*), panel instan diagnostik jaringan (ping status & last active time), serta tombol ekspor laporan.
    • Halaman Settings (Pengaturan Sensitivitas): Formulir untuk memodifikasi tingkat kepekaan alarm.
  2. Antarmuka Web Admin Dashboard (Administrator):
    • Halaman Login Admin: Portal khusus yang mengamankan konsol konfigurasi admin menggunakan kredensial yang tersimpan di file .env.
    • Halaman Dashboard Admin: Tabel inventori terpusat yang memuat seluruh ID alat, status koneksi, PPM aktual, dan email pemilik dengan fitur pencarian real-time.
    • Panel Kelola Perangkat (CRUD & Code): Menu untuk meregistrasikan ID alat baru (otomatis membuat QR Code), mengedit/menghapus perangkat, serta menyalin firmware program C++ Arduino (.ino).

4.2 Pengujian

Bagian ini menjabarkan seluruh proses pengujian otomatis yang dilakukan oleh tim penguji untuk memverifikasi keandalan fungsionalitas sistem CarbonSense menggunakan perangkat pengujian otomatis.

4.2.1 Perencanaan Pengujian

Perencanaan pengujian dilakukan dengan menetapkan tools pengujian, cakupan fungsionalitas, teknik, dan jadwal pengujian sebagai berikut:

  1. Instalasi Tools Pengujian (Selenium IDE):
    • Membuka peramban Microsoft Edge di komputer penguji.
    • Mengunjungi Edge Add-ons Store dan mengunduh ekstensi resmi **Selenium IDE**.
    • Setelah terinstal, klik ikon Selenium IDE pada bilah alat browser untuk membuka jendela utama.
    • Pilih opsi "Record a new test in a new project", beri nama proyek (e.g. *CarbonSense Testing*), masukkan URL dasar http://localhost:3000, dan klik OK untuk memulai perekaman interaksi browser.
  2. Cakupan Fungsionalitas: Pengujian mencakup 13 modul fungsionalitas utama sistem CarbonSense, termasuk registrasi, login, onboarding profil AI, edit profil & password, penautan perangkat (QR Code), reaktivasi dashboard, asisten cerdas chat AI, navigasi histori tanggal, ekspor laporan, pengaturan sensitivitas, autentikasi admin, manajemen dasbor admin, dan autentikasi logout.
  3. Teknik Pengujian: Teknik yang digunakan adalah **Black-Box Testing** dengan pendekatan **Equivalence Partitioning (EP)** untuk mengklasifikasikan rentang input valid/invalid, serta **Boundary Value Analysis (BVA)** untuk menguji batas ekstrem parameter (misalnya panjang kata sandi minimal 6 karakter).
  4. Jadwal dan Pengawakan: Pelaksanaan pengujian dilakukan secara berkala dan diotomasi penuh oleh tim penguji perangkat lunak dengan penjadwalan terstruktur selama fase siklus pengembangan perangkat lunak (SDLC).

BAB 5
KESIMPULAN DAN SARAN

5.1 Kesimpulan

Dari 38 pengujian fungsionalitas yang telah direncanakan dan dieksekusi secara otomatis menggunakan Selenium IDE dan Selenium WebDriver pada sistem pemantauan kualitas udara CarbonSense, seluruh 38 pengujian dinyatakan berhasil (pass) dengan persentase keberhasilan sebesar 100%. Selama siklus pengujian berlangsung, tim penguji berfokus pada pengujian aspek fungsionalitas dasar seperti modul login dan registrasi, alur wajib pengisian kuesioner onboarding kesehatan, validasi parameter penautan perangkat (QR Code Device Binding), hingga sinkronisasi data sensor MQ135 secara real-time.

Pada awal tahap pengembangan pengujian, tim penguji sempat mengidentifikasi beberapa defect penting, di antaranya adalah:

  1. Validasi batas panjang karakter registrasi akun (username dan password) yang belum terikat secara ketat.
  2. Penautan perangkat fisik menggunakan tautan URL parameter (login?device=...) yang sempat menerima sembarang kode perangkat.

Namun, kendala tersebut telah berhasil diselesaikan secara tuntas. Saat ini, registrasi akun pengguna hanya dapat berhasil jika kata sandi diisi minimal 6 karakter. Sementara itu, untuk penautan alat lewat scan QR, sistem kini memvalidasi parameter Device ID secara ketat terhadap database admin; apabila parameter yang dikirim di luar dari yang didaftarkan oleh admin, halaman penautan secara otomatis dikosongkan demi mencegah terjadinya penautan ilegal.

5.2 Saran

Untuk pengembangan dan peningkatan sistem di masa mendatang, tim penguji memberikan beberapa saran perbaikan sebagai berikut:

  1. Peningkatan Manajemen State Pengguna: Disarankan untuk menambahkan animasi pemuatan (skeleton loading state) saat sistem menyinkronkan data parameter PPM kualitas udara dari database Supabase PostgreSQL ke dashboard frontend guna meningkatkan kenyamanan visual pengguna.
  2. Validasi Sisi Server (Backend Validation): Perlu ditambahkan validasi skema yang lebih ketat pada lapisan backend (database constraint) untuk parameter penautan perangkat, sebagai proteksi lapis kedua selain pengosongan halaman pada antarmuka frontend.
  3. Mekanisme Penanganan Gangguan Sensor: Disarankan untuk menambahkan sistem peringatan berupa notifikasi surat elektronik (e-mail) otomatis kepada pengguna apabila status perangkat terdeteksi Offline atau tidak aktif selama lebih dari 12 jam berturut-turut.
